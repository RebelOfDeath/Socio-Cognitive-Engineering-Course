# SCE Wiki Sync

Tools to edit the group's [XWiki](https://xwiki.ewi.tudelft.nl/xwiki/wiki/sce2026group04) content locally (in your editor, under git) and sync changes to/from the live wiki via its REST API.

## Layout

- `wiki-sync/sync.py` — the sync tool (stdlib-only Python, no install needed beyond `certifi`).
- `wiki-sync/.env` — your credentials (gitignored, never committed). Copy `wiki-sync/.env.example` to create it.
- `wiki-content/` — the wiki's pages, as local files. This is what you edit and commit.
- `OUTLINE.md` — the page tree with links to the files, regenerated by every `pull` and `push`.

## Setup

```
cd wiki-sync
cp .env.example .env
# edit .env and fill in XWIKI_USER / XWIKI_PASSWORD
pip install certifi   # only needed if `python3 -c "import certifi"` fails
```

## Usage

Run these from the repo root:

```
python3 wiki-sync/sync.py pull            # download everything from the wiki
python3 wiki-sync/sync.py status          # what push would do (no network)
python3 wiki-sync/sync.py push            # create, update, retitle and delete pages
python3 wiki-sync/sync.py push <file>     # just one page (never deletes anything)
python3 wiki-sync/sync.py layout          # re-file pages under their titles (no network)
```

Typical loop: `pull` to get the latest, edit files in `wiki-content/`, `status` to see what push would do, `push` to publish.

## The tree

`wiki-content/` mirrors the wiki's page tree:

```
wiki-content/
├─ 0 Index.xwiki                       ← the wiki's home page
└─ 1 Foundation/                       ← page "1 Foundation"
   ├─ 0 Index.xwiki                    ← what "1 Foundation" itself says
   ├─ a1 Situated Activities/          ← page "a1 Situated Activities"
   │  ├─ 0 Index.xwiki
   │  ├─ a1.1 Garden walks, alone and in pairs.xwiki
   │  └─ a1.3 Morning care - situated activities.xwiki
   └─ d Foundation Coherence/
      └─ ...
```

- **A page without children is a file** named after its title. **A page with children is a folder** named after its title. On the wiki a page can have text *and* children, but a file system entry can't be both a file and a folder, so the folder's own text lives in the `0 Index.xwiki` inside it. `0 Index` is not a page of its own on the wiki: it *is* the folder's page.
- **`wiki-content/0 Index.xwiki` is the wiki's home page** (`Main.WebHome`). Every other file or folder at the top is a top-level page.
- **Titles are names.** Titles follow (number)(space)(name), without a full stop after the number: `1 Foundation`, `a1.1 Garden walks, alone and in pairs`. Characters Windows can't put in a file name become `-` in the name only (`IDP: Title` → `IDP- Title.xwiki`); the `title:` line keeps the exact title.
- **Renaming** a file or folder retitles the page on `push`; a retitle on the wiki renames it on `pull`. Editing the `title:` line works too. A page's address (its URL) keeps the name it was created with.
- **New pages** need no metadata: add `<title>.xwiki` in the folder of the page it belongs under, or a new folder for a page with children, and `push`. A folder without a `0 Index.xwiki` gets an empty one. To give a page its first child, make a folder with the page's exact file name (without `.xwiki`) next to it and put the new file inside; `push` moves the page's file into the folder as its `0 Index.xwiki`. A folder left with only its `0 Index.xwiki` turns back into a plain file.
- **Deleting** a file (or folder) and pushing deletes the page from the wiki. `push` lists the pages and asks first (`--yes` skips the question), and it never deletes a page someone has edited on the wiki since your last sync; `pull` brings that one back instead. The home page is never deleted.
- **Moving** a page to another parent needs the wiki's own Page Actions → Move/Rename, then `pull`: the REST API has no move.

Each file starts with a metadata block the tool uses to track sync state:

```
%%WIKI-SYNC-META%%
href: <REST API URL for this page>
title: <page title>
synced_title: <title at last sync; don't hand-edit>
syntax: xwiki/2.1
version: <last-synced version, e.g. 3.1>
hash: <sha256 of the content below, at last sync>
%%WIKI-SYNC-META%%
<page content in XWiki 2.1 syntax — edit this part>
```

`wiki-content/.sync-state.json` lists the pages that were on the wiki at the last `pull` or `push`. It is how `push` tells a page you deleted from one a teammate has just created (which `pull` downloads instead). Commit it; don't hand-edit it.

Content stays in native XWiki syntax (`**bold**`, `= Heading =`, `{{macro}}...{{/macro}}`, etc.) rather than being converted to Markdown, so nothing gets mangled on push. See [XWiki Syntax](https://xwiki.ewi.tudelft.nl/xwiki/wiki/sce2026group04/view/XWiki/XWikiSyntax) for a reference. Links to other pages use their reference, e.g. `[[a2.1 Residents, family and staff>>doc:1 Foundation.a2 Stakeholders.a2\.1 Residents, family and staff.WebHome]]` (a `.` inside a name is written `\.`).

## Attachments (images, PDFs, etc.)

A page's attachments live in a `<file name>.attachments/` folder next to its file; for a folder's page that is `0 Index.attachments/` inside the folder:

```
wiki-content/2 Specification/a2 Personas and Profiles/a2.1 Human Personas.xwiki
wiki-content/2 Specification/a2 Personas and Profiles/a2.1 Human Personas.attachments/01.jpg
wiki-content/2 Specification/a2 Personas and Profiles/a2.1 Human Personas.attachments/.sync-manifest.json
```

This is **two-way**: `pull` downloads new/changed attachments, and `push` uploads any file you add, replace, or edit in that folder. The `.sync-manifest.json` file in each folder is bookkeeping (per-file hash/version at last sync) — don't hand-edit it, but do commit it. Deleting a local attachment file does **not** delete it from the wiki.

## Conflict handling

Multiple people edit this wiki, so the tool checks versions before overwriting anything, for both pages and attachments:

- **`push`** compares the wiki's current version to the version you last synced. If someone else changed the page/attachment in the meantime, it refuses to push and tells you to `pull` first — no silent overwrites.
- **`pull`** won't clobber local edits: if you've changed something locally and the wiki hasn't changed, your local copy is left alone. If *both* changed, the wiki's version is saved as `<name>.remote.xwiki` (or `<name>.remote.<ext>` for attachments) next to yours so you can merge by hand.

## Excluding spaces

`XWIKI_EXCLUDE_SPACES` in `wiki-sync/.env` names top-level spaces the tool leaves alone: `XWiki` (accounts), `Menu` and `Diagram` (the applications' own pages) and `Sandbox`. Apart from the home page, the `Main` space holds XWiki's own pages and is skipped too.

`wiki-sync/delete.py` deletes pages (or a whole subtree with `--space`) directly on the wiki, including outside the synced tree; run `pull` afterwards.

## Walking with meaning PDF

`node wiki-content/make-walking-pdf.js` builds `Walking with meaning - chapters.pdf` from the current-concept pages of `1 Foundation` and `2 Specification` (index pages and the separate Morning care pages are left out). Both files stay local: the sync only handles `.xwiki` files and `.attachments` folders.
